# Синтетические данные и A/B-эксперимент

У платформы пока нет реальных пользователей, поэтому схема событий, метрики и дизайн эксперимента проверяются на синтетических данных. Названия событий и поля совпадают с тем, что пишет платформа (`backend/src/lib/events.js`, таблица `events_bronze`), поэтому тот же код подходит и для реальных данных.

Приложение эта папка не затрагивает: отдельный Python-код, backend и клиент его не используют.

## Итоги

**[results/README.md](results/README.md)** — все итоговые цифры эксперимента и метрик продукта с графиками (для слайда и отчёта), рядом — таблицы CSV, графики PNG и отчёт `results/Отчёт.docx`.

## Что здесь

| Файл | Что делает |
|---|---|
| `community_events_synthetic.py` | **Модуль генерации синтетики одним файлом**. Схема событий и контракт данных, сборщик событий `EventCollector` для логирования по схеме приложения, синтетические пользователи с группами A/B, дефекты в сырых данных, серебряный слой и карантин, золотой слой (воронка A/B, защитные метрики, WECU, когортное удержание, CAC по каналам). Результат — CSV и графики в `output/` |
| `ab_experiment/generate.py` | Расширенный генератор для эксперимента: сегменты пользователей, заложенный эффект, «грязь» в данных |
| `ab_experiment/pipeline.py` | Bronze → Silver → Gold: проверки качества, карантин с причинами, склейка гостя с аккаунтом, витрины |
| `ab_experiment/analysis.py` | Расчёт эксперимента: размер выборки, проверка деления 50/50 (SRM), z-тест двух долей, защитные метрики, сегменты с поправкой Бонферрони, мониторинг с границами О'Брайена–Флеминга, A/A-тест, графики |
| `ab_experiment/ab_test.ipynb` | Ноутбук: всё по шагам, с пояснениями и посчитанными результатами (открывается прямо на GitHub) |
| `ab_experiment/make_notebook.py` | Пересобирает и прогоняет ноутбук |
| `make_results.py` | Собирает итоги в `results/`: страницу с цифрами, графики, таблицы |

## Как запустить

```bash
cd analytics/synthetic
pip install -r requirements.txt

# Модуль синтетики (одним файлом):
python community_events_synthetic.py      # -> output/*.csv, output/*.png

# Эксперимент:
cd ab_experiment
python generate.py && python pipeline.py && python analysis.py
python make_notebook.py                   # пересобрать ноутбук
cd .. && python make_results.py           # итоги -> results/
```

Результат воспроизводится: генераторы используют фиксированный `seed = 42`. Сырые данные в репозиторий не кладутся (`.gitignore`) — за минуту получаются запуском; итоговые таблицы и графики лежат в `results/`.

## Главные таблицы

| Файл | Что в нём |
|---|---|
| `output/bronze_events.csv` | Сырые события, как пришли из приложения, с дефектами |
| `output/silver_events.csv` | Очищенные события, время в UTC, `person_id` после склейки |
| `output/quarantine_events.csv` | Отбракованные события с причиной |
| `output/experiment_users.csv` | Одна строка на участника эксперимента: группа A/B, сегмент, канал, шаги воронки — вход для расчёта эксперимента |
| `output/gold_*.csv` | Витрины: воронка A/B, защитные метрики, WECU по неделям, когорты, CAC |

## Важно

Все вероятности в генераторах — допущения модели, а не измерения (константы `P_*` и `Config`). Модуль проверяет, что метрики и дизайн эксперимента работают и находят заложенный эффект, а не измеряет продукт.
